# Vibecoding 实战守则

核心信念：**AI 写代码的速度是人的 100 倍，所以 AI 引入 bug 的速度也是人的 100 倍——验证必须比生成更快、更严**。每一条例都来自真实事故，不是理论。

## 一、上线前四道验证闸门（全过才能推）

1. **语法闸**：改动的 JS 必须过 `node --check` 或 `new Function(src)` 解析。
2. **数据闸**：改 events.js 等数据文件，必须沙箱执行（`vm.runInNewContext`）+ 校验条数/去重/来源 key。已有工具：`node bump-version.mjs`（版本推导）、scrape.js 内置写盘自检。
3. **渲染闸**：改 index.html，必须在 DOM 桩里完整执行 init + render，确认无运行时异常、产物非空（曾因变量名 mu/mus 笔误导致全页空白上线）。
4. **真数据闸**：用真实数据跑核心函数并抽查输出（曾发现"北大 9/15"这种不存在的日期串进提示）。

## 二、发布纪律

- **版本号**：一律 `node bump-version.mjs` 自动推导（按系统日期+既有日志），**严禁手工递增**——已两次跨零点用错日期序列。
- **BUILD 标记**：index.html 每次部署必须更新 `var BUILD="..."`，否则旧缓存页面的自检无法察觉差异。
- **更新日志**：新版本必须有对应 CHANGELOG 条目（key = DATA_VERSION）；纯修正可不写条目（静默，不弹窗）。
- **推送后**：确认 GitHub Actions 部署 success + 线上 DATA_VERSION 已更新。
- 页面内置版本自检（checkRemote）：不要动它的正则形态限制。

## 三、数据与状态设计规范

- **稳定 key**：记录以 `日期|时间|单位` 为键，数据增删不串位。
- **缓存键要有区分度**：缓存键若为"日期|学校"这类弱键，不同单位簇会互相覆盖（国开行提示被清空、国新串成别家）。键必须包含单位簇或唯一标识。
- **初始化用对类型**：数组 `||[]`，对象 `||{}`——写反一个就是全页崩溃。
- **数据与用户状态分离**：叉掉/撤销存 localStorage（稳定 key），数据更新永不破坏用户记录。
- **写盘自检闸门**：任何脚本写数据文件前先解析验证，失败即回滚放弃——语法损坏的数据永远不能上线。

## 四、事故案例库（症状 → 根因 → 防呆）

| 症状 | 根因 | 防呆 |
|---|---|---|
| 全页空白（语法损坏的数据上线） | 多天块插入漏逗号 + 无写盘校验 | 写盘自检 + 上线前沙箱执行 |
| 全页空白（渲染崩溃） | 变量名笔误 mu/mus、`||{}` 误用 | 渲染测试桩（render_test） |
| 提示互相覆盖 / 标错单位 | 缓存键"日期\|学校"跨簇冲突 | 缓存键加单位簇前缀 |
| 版本号倒退（V9.9.2→V9.9.1） | 跨零点手工递增旧序列 | bump-version.mjs 按日期推导 |
| 每 1.5 秒弹"已更新"误报 | 自检正则匹配到自己的源码 | 正则限定版本形态 V\d+\.\d+\.\d+ |
| 跨校提示引用已隐藏的场次 | 预计算未过滤非聚焦学校 | 预计算入口统一走 passF 过滤 |
| AI 清单含幻觉场次/伪引文 | 未回源核实 | 逐条回原文比对后才可入库 |

## 五、AI 协作纪律

- **多智能体分工 + 互相审计**：不同 Agent 各管一段（如：一个抓数据、一个管部署），任何一方的改动对另一方必须可见、可追溯（commit 署名清晰、变更写共享备忘录）。
- **AI 产出必须人工回源核验**：AI 生成的清单默认含幻觉（实测某 AI 约 8% 条目不实且伪造引文），逐条对照原始来源后才可采用。
- **跨零点警觉**：23:50 后提交，版本号、日期字段一律先查系统时钟，别信上一个版本的序列。
- **根因优先**：每次故障回溯到根因并固化为防呆机制（写进代码或本守则），不打补丁了事。
- **诚实报告**：测试没跑就说没跑，故障窗口如实告知（如"影响约 10 分钟"），不粉饰。

## 六、已知薄弱点（待强化）

- 渲染测试桩尚未覆盖移动端视口（手机布局靠 CSS 媒体查询，未做断言）。
- 抓取脚本的静默失败（如站点改版返回 0 条）只有日志无主动告警。
- 多端写同一仓库仍靠 git rebase 兜底，无锁。
