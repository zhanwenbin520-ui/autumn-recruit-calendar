# Vibecoding 实战守则

核心信念：**AI 写代码的速度是人的 100 倍，所以 AI 引入 bug 的速度也是人的 100 倍——验证必须比生成更快、更严。**

每一条规则都来自真实事故，不是理论。本技能源自一个 10 天迭代 80+ 版本、服务 180 名真实用户的在线产品（北京高校秋招日历），全程开源可查。

---

## 一、五步最小路径（引导用户从痛点到产品）

当用户说"我想做一个 XX"时，按此路径引导：

1. **痛点清单化**——"我每天重复在做的一件烦事"是什么？拆成 3-4 个具体问题
2. **先侦察后动手**——动手之前先用 AI 搞清楚状况（调研、对比、核实）
3. **最小版本**——用大白话向 AI 要一个"能用"的版本，当天上线，别要十全十美
4. **真实使用**——亲手用一周，记下每一次不爽
5. **反馈迭代**——把不爽一条条丢回给 AI，一次改一个；敢于分享给真实用户

架构上有一个高价值起点：**数据与界面分离**。会频繁变化的部分单独放一个文件，稳定的部分单独放——这一个决定让后续所有自动化成为可能。

---

## 二、上线前四道验证闸门（全过才能推）

1. **语法闸**：改动的 JS 必须过 `node --check` 或 `new Function(src)` 解析。
2. **数据闸**：改数据文件必须沙箱执行（`vm.runInNewContext`）+ 校验条数/去重/来源字段。
3. **渲染闸**：改页面必须在 DOM 桩里完整执行 init + render，确认无运行时异常、产物非空。
4. **真数据闸**：用真实数据跑核心函数并抽查输出（日期、学校、数量是否合理）。

> 四道闸门的成本约 1 分钟，能拦住：语法损坏、数据冲突、变量名笔误、渲染崩溃——全部是真实发生过的上线事故。

## 三、发布纪律

- **版本号**：按 `V{月}.{日}.{当日序号}` 自动推导（扫描既有更新日志取当日最大序号 +1），**严禁手工递增**——跨零点后必错。
- **BUILD 标记**：页面每次部署必须更新内嵌 BUILD 常量，否则旧缓存页面的自检无法察觉差异。
- **更新日志**：新版本必须有对应条目（key = 版本号）；数组元素之间**记得逗号**；纯文案微调可不弹窗。
- **推送后必核**：确认自动部署 success + 线上版本号已更新 + 核心功能标记存在。
- **页面内置版本自检**：定时核对线上版本与 BUILD，发现本页过旧立即提示一键刷新——缓存问题对所有用户自动消失。

## 四、数据与状态设计规范

- **稳定 key**：用户状态（标记/分级/撤销）以业务字段组合为键（如 `日期|时间|单位`），数据增删不串位。
- **缓存键要有区分度**：弱键（如"日期|学校"）会被不同业务簇互相覆盖——键必须包含唯一标识（如单位簇 ID）。
- **初始化类型要对**：数组 `||[]`，对象 `||{}`——写反一个就是全页崩溃。
- **数据与用户状态分离**：数据文件天天变，用户记录永不受影响。
- **写盘自检闸门**：任何脚本写数据文件前先解析验证，失败即回滚放弃——语法损坏的数据永远不能上线。
- **静默失败是最大敌恶**：所有网络/写入操作必须有失败反馈。"没报错"不等于"成功了"。

## 五、事故案例库（症状 → 根因 → 防呆）

| 症状 | 根因 | 防呆 |
|---|---|---|
| 全页空白（语法损坏的数据上线） | 自动插入漏逗号 + 无写盘校验 | 写盘自检 + 上线前沙箱执行 |
| 全页空白（渲染崩溃） | 变量名笔误（mu/mus）、初始化误用 `||{}` | 渲染测试桩 + 真数据非空路径测试 |
| 提示互相覆盖 / 标错单位 | 缓存键"日期\|学校"跨业务簇冲突 | 缓存键加唯一簇前缀 |
| 版本号倒退（跨零点） | 手工递增旧序列 | bump-version 工具按日期推导 |
| 弹窗死循环误报 | 自检正则匹配到自己的源码 | 正则限定目标形态（V\d+\.\d+\.\d+） |
| 提示引用已隐藏的场次 | 预计算未过滤不可见条目 | 预计算入口统一走可见性过滤 |
| AI 清单含幻觉场次/伪引文 | 未回源核实 | 逐条回原文比对后才可入库 |
| 手机上交互失效（hover 类功能） | 触屏没有悬停 | 关键内容不依赖 hover；触屏判定用 pointer:coarse 而非 ontouchstart |

## 六、AI 协作纪律

- **多智能体分工 + 互相审计**：不同 Agent 各管一段，改动互相可见、可追溯（commit 署名清晰、变更写共享备忘录）。
- **AI 产出必须人工回源核验**：AI 生成的清单默认含幻觉（实测某 AI 约 8% 条目不实且伪造引文）。
- **并行写同一仓库**：pull 前先 commit/stash；任何一方的改动消失，先查是否被对方的 pull/rebase 覆盖。
- **诚实报告**：测试没跑就说没跑，故障窗口如实告知（如"影响约 10 分钟"），不粉饰。

---

## 七、已知薄弱点（诚实清单）

- 渲染测试桩未覆盖移动端视口断言。
- 数据源静默失败（改版返回 0 条）只有日志无主动告警。
- 多端并发写同一仓库仍靠 git rebase 兜底。
